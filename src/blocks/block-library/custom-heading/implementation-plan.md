# `ystdb/custom-heading`実装計画

更新日: 2026-08-20

## 目的

コア見出しブロックの編集体験を土台にしながら、メインテキスト、サブテキスト、区切り線を1ブロックで扱える見出しブロックを完成させる。

コアブロックを複数組み合わせなくても、見出しに必要な設定と再利用を1ブロック内で完結できることを優先する。

## 結論

-   タイポグラフィ、外側余白、内側余白、枠線、角丸、文字色、背景色は、可能な限りBlock Supportsを使う。
-   コア設定はブロック全体の基準であり、タイポグラフィはメインテキストの基準として扱う。
-   独自パネルも、コアブロックと同じく`+`メニューから必要な設定を表示する`ToolsPanel`形式へ統一する。
-   単一設定とレスポンシブ設定は、属性、UIパネル、リセット操作を完全に分ける。両方に値がある場合は、該当画面幅のレスポンシブ値を優先する。
-   サブテキストと区切り線だけを独自設定として追加する。
-   独自の見た目は個別のトップレベル属性へ分散させず、`style.ystdb`配下へまとめる。同じ`ystdb/custom-heading`同士では、WordPressの「スタイルをコピー」「スタイルを貼り付け」でコア設定と独自設定を一緒に移せる構造にする。
-   設定項目は共通部品化し、同種の設定であればラベルと保存先のキーを変えるだけで再利用できる構造にする。
-   サブテキストが空なら保存HTMLは`h1`〜`h6`単体にする。サブテキストがある場合だけ`hgroup`を使う。
-   区切り線は装飾要素をHTMLへ追加せず、見出し要素の疑似要素で表示する。これにより`hgroup`の内容モデルを壊さない。
-   現在のβ版も公開済みブロックとして扱い、保存HTMLまたは属性構造を変える箇所には`deprecated`と`migrate`を用意する。

## 保存HTML

### サブテキストなし

```html
<h2 class="wp-block-ystdb-custom-heading ystdb-custom-heading">
	メインテキスト
</h2>
```

余白、枠線、角丸、背景、メインテキストのタイポグラフィは、この見出し要素へ適用する。

### サブテキストあり

```html
<hgroup class="wp-block-ystdb-custom-heading ystdb-custom-heading has-sub-text">
	<h2 class="ystdb-custom-heading__main">メインテキスト</h2>
	<p class="ystdb-custom-heading__sub">サブテキスト</p>
</hgroup>
```

余白、枠線、角丸、背景は`hgroup`へ適用する。コアのタイポグラフィをメインテキストの基準値として`hgroup`から継承し、サブテキストは独自設定で上書きする。

サブテキストを上側へ配置する場合は、`p`、見出しの順で保存する。`hgroup`では見出しの前後に`p`を配置できる。

区切り線は次の位置へ疑似要素で表示する。

-   サブテキストが下側なら、メインテキストの`::after`
-   サブテキストが上側なら、メインテキストの`::before`
-   サブテキストがなければ、メインテキストの`::after`

## 設定の責務

| 対象           | 設定                                                                   | 保存先                           | UI                     |
| -------------- | ---------------------------------------------------------------------- | -------------------------------- | ---------------------- |
| ブロック全体   | 外側余白、内側余白                                                     | `style.spacing`                  | コア                   |
| ブロック全体   | 枠線、角丸                                                             | `style.border`                   | コア                   |
| ブロック全体   | 文字色、背景色                                                         | コアの色属性と`style.color`      | コア                   |
| メインテキスト | フォントサイズ、行の高さ、文字間隔、太さ、スタイル、フォント、文字揃え | コアの属性と`style.typography`   | コア                   |
| メインテキスト | 画面幅別フォントサイズ                                                 | `style.ystdb.responsive.main`    | 独自レスポンシブパネル |
| サブテキスト   | 内容、上下位置                                                         | `subText`、`subTextPosition`     | 独自                   |
| サブテキスト   | 色、タイポグラフィ、余白                                               | `style.ystdb.subText`            | 独自単一設定パネル     |
| サブテキスト   | 画面幅別設定                                                           | `style.ystdb.responsive.subText` | 独自レスポンシブパネル |
| 区切り線       | 表示、色、太さ、長さ、線種、上下余白                                   | `style.ystdb.divider`            | 独自単一設定パネル     |
| 区切り線       | 画面幅別の長さと余白                                                   | `style.ystdb.responsive.divider` | 独自レスポンシブパネル |

`content`と`subText`には`role: "content"`を付ける。見た目のコピーで本文が置き換わらないことを、属性設計とテストの両方で保証する。

-   `typography.fontSize`
-   `typography.lineHeight`
-   `typography.textAlign`
-   フォントファミリー、文字太さ、文字スタイル、文字間隔に対応するタイポグラフィサポート
-   `spacing.margin`
-   `spacing.padding`
-   `border.color`
-   `border.style`
-   `border.width`
-   `border.radius`
-   `color.text`
-   `color.background`
-   `align: ["wide", "full"]`
-   `anchor`

現在の独自タイポグラフィ属性は、新しいコア属性へ移行する。レスポンシブ指定のようにコアだけでは足りない機能は、コア値を通常値として残したうえで`style.ystdb.responsive`から上書きする。

## 単一設定とレスポンシブ設定

単一設定とレスポンシブ設定は同じ値を切り替えて編集するモードではなく、同時に保持できる別の設定として扱う。

```ts
const effectiveValue = responsiveValue?.[ device ] ?? singleValue;
```

優先順位は次のとおり。

-   現在の画面幅にレスポンシブ値がある場合は、その値を使う。
-   現在の画面幅にレスポンシブ値がない場合は、単一設定を使う。
-   他の画面幅に設定されたレスポンシブ値は引き継がない。
-   レスポンシブ値を削除すると、単一設定へ戻る。

たとえば、単一設定が`32px`、タブレットだけが`24px`なら、PCとスマートフォンは`32px`、タブレットは`24px`になる。

単一設定のリセットでは単一設定だけを削除し、レスポンシブ設定は残す。レスポンシブ設定のリセットではレスポンシブ設定だけを削除し、単一設定は残す。パネルの「すべてリセット」も、そのパネルが担当する保存先だけを対象にする。

スタイル出力では、通常値を直接出力したあとにレスポンシブCSSで上書きするだけの実装に依存しない。コアが出力するインラインスタイルよりレスポンシブ指定が確実に優先されるよう、共通のスタイル解決関数とCSSカスタムプロパティで最終値を組み立てる。

## `ToolsPanel`共通基盤

`ToolsPanel`と`ToolsPanelItem`は今後の独自設定パネルの標準にする。

-   値がある項目は自動的に表示する。
-   頻繁に使う最小限の項目だけ`isShownByDefault`で初期表示する。
-   追加項目は`+`メニューから表示する。
-   `label`は表示名と項目識別子を兼ねるため、同じパネル内で重複させない。
-   項目をメニューから外した場合は、その項目の値だけを削除する。
-   「すべてリセット」では、そのパネル内の値だけを削除する。
-   単一設定パネルとレスポンシブ設定パネルは別々の`ToolsPanel`にする。

`ToolsPanel`はExperimental APIのため、現在の`src/aktk-block-components/wp-controls/tools-panel/`を互換レイヤーとして残す。各ブロックと各設定部品は`@wordpress/components`のExperimental APIを直接importしない。

## 設定項目の共通化

共通部品は「値の入力」と「属性への接続」を分ける。

### 入力部品

入力部品は保存先を知らず、次の最小限のpropsだけを受け取る。

-   `label`
-   `value`
-   `onChange`
-   設定の種類に固有の補助props

通常値の入力部品と、PC、タブレット、スマートフォンを編集するレスポンシブ入力部品も分ける。現在の`ResponsiveSelectTab`を内包する部品は段階的に分解し、タブ切り替えを新しい共通部品へ持ち込まない。

### 属性接続部品

`ToolsPanelItem`との接続は、共通の属性接続部品が担当する。

```tsx
<SettingToolsPanelItem
	label={ __( '外側余白', 'ystandard-blocks' ) }
	valuePath="style.ystdb.subText.spacing.margin"
	{ ...blockProps }
>
	{ ( controlProps ) => <SpacingControl { ...controlProps } /> }
</SettingToolsPanelItem>
```

属性接続部品は`label`と`valuePath`から、次を共通処理する。

-   現在値の取得
-   `hasValue`
-   値の更新
-   `onDeselect`
-   項目単位のリセット
-   空になった親オブジェクトの削除
-   `ToolsPanel`の「すべてリセット」への参加

同じ種類の設定では、ブロック側はラベルと`valuePath`を変えるだけで利用できるようにする。設定固有の優先順位やCSS生成をUI部品へ持たせない。

### レスポンシブ値の共通型

レスポンシブ設定は次の形へ統一する。

```ts
type ResponsiveValue< T > = {
	desktop?: T;
	tablet?: T;
	mobile?: T;
};
```

フォントサイズ、余白、幅、高さ、区切り線などは同じ型と値解決関数を使う。設定ごとの差は、値`T`の型、ラベル、保存先、CSSプロパティの対応だけに限定する。

## スタイルコピー

現在のWordPressは、コピー元と貼り付け先の両方が対応するコアのスタイル属性だけを貼り付ける。`subTextSize`のような独自トップレベル属性は対象にならない。

一方、Block Supportsが使う`style`属性は全体がコピー対象になる。そこで、独自の見た目を`style.ystdb`配下へまとめる。

この方式で保証する範囲は次のとおり。

-   `ystdb/custom-heading`から`ystdb/custom-heading`へのコピーでは、コア設定とサブテキスト・区切り線の見た目を一緒にコピーする。
-   メインテキストとサブテキストの内容はコピーしない。
-   サブテキストの有無はコピーしない。貼り付け先の構造を維持し、サブテキスト用スタイルはサブテキストがある場合だけ表示へ反映する。
-   コアブロックとの間では、コアが共通対応する設定だけを利用対象とする。独自設定の相互運用は保証しない。

`style.ystdb`はWordPressのStyle Engineが未対応のキーとしてCSS出力を無視する。ブロック側で必要な値だけを読み取り、CSSカスタムプロパティへ変換する。

## 編集UI

サイドバーは次の構成にする。

-   コアの「色」
-   コアの「タイポグラフィ」
-   コアの「サイズ」または余白設定
-   コアの「枠線」
-   `ToolsPanel`形式の「サブテキスト」
-   `ToolsPanel`形式の「区切り線」
-   `ToolsPanel`形式の「レスポンシブ」
-   「テーマスタイル」

サブテキストは、サイドバーで内容だけを入力させず、キャンバス上の`RichText`で直接編集できるようにする。サイドバーには表示切り替え、上下位置、詳細スタイルを置く。

区切り線は初期状態で非表示にする。表示を有効にしたときだけ詳細設定を表示する。

設定数を抑えるため、通常値はコアUIまたは対象ごとの単一設定パネルへ集約し、画面幅別設定だけを独立した「レスポンシブ」パネルへまとめる。同じ入力欄のタブで単一設定とレスポンシブ設定を切り替えない。

## 互換性と変換

### 現在のβ版からの移行

現在の保存関数を`deprecated`へ移し、次の属性を新構造へ移す。

-   `textColor`、`customTextColor`
-   `fontSize`、`customFontSize`
-   `fontWeight`、`fontStyle`、`lineHeight`、`letterSpacing`、`fontFamily`
-   `textAlign`
-   `margin`、`responsiveMargin`
-   `padding`、`responsivePadding`

既存投稿を開いた直後に「このブロックには、想定されていないか無効なコンテンツが含まれています」が出ないことを必須条件にする。

### `ystdb/heading`からの変換

現在の変換はサブテキストなどを破棄するため、そのまま正式機能にしない。

新実装では次を移す。

-   メインテキストと見出しレベル
-   文字揃え、色、タイポグラフィ、レスポンシブフォントサイズ
-   外側余白
-   サブテキスト、上下位置、色、タイポグラフィ、レスポンシブフォントサイズ
-   区切り線の表示、色、長さ、太さ、上下余白

従来の区切り画像は新ブロックの初期完成範囲に含めない。区切り画像が設定された旧ブロックは変換対象から除外し、データを失う変換を表示しない。

### コアブロックとの変換

-   `core/heading`からは、内容、レベル、コア対応スタイルをそのまま移す。
-   `core/heading`へ戻す場合は、`style.ystdb`を除外し、コア対応スタイルだけを渡す。
-   サブテキストまたは区切り線がある場合は、情報が失われる単一の`core/heading`変換を表示しない。

## WordPressバージョン

プラグインヘッダーはWordPress 6.4以上、配布用JSONはWordPress 6.7以上になっており、現在不一致がある。

`typography.textAlign`はWordPress 6.6以降のため、実装前に最低要件をWordPress 6.7へ統一する。これにより、独自の文字揃えコントロールと互換用分岐を増やさずに済む。

## 現在のブランチの扱い

-   実装開始前に`origin/master`を取り込み、依存関係更新後の状態へ合わせる。
-   `supports.align: ["wide", "full"]`は残す。
-   現在の独自`AlignmentControl`は、`typography.textAlign`へ置き換える。
-   現在の`ToolsPanel`ラッパーは、Experimental APIを隔離する共通基盤として残し、型とリセット処理を整える。
-   `Panel`の`className`対応は、`ToolsPanel`を既存インスペクターへ配置するために必要か確認し、必要な場合だけ残す。
-   調査開始時点で既存の未コミット差分はなかった。現在の4コミットは作業履歴として保持し、取り込み方法は実装開始時に決める。

## 実装順

### 基盤整理

-   `origin/master`を取り込む。
-   WordPress最低要件を6.7へ統一する。

-   単一入力部品とレスポンシブ入力部品を分離する。

-   コア属性を使うように`edit`、`save`、型、ユーティリティを整理する。
-   現在のβ版用`deprecated`とマイグレーションテストを追加する。

### サブテキスト

-   `subText`、`subTextPosition`と`style.ystdb.subText`を追加する。
-   キャンバス上で直接編集できるUIを追加する。
-   値の有無に応じて`h1`〜`h6`単体と`hgroup`を切り替える。

### 変換とスタイルコピー

-   `ystdb/heading`からの変換を機能欠落なしに更新する。

-   内容と構造がスタイルコピーで変わらないことをテストする。

### 仕上げ

-   ブロック名から「β版」を外す条件を確認する。

-   同じカスタム見出し間のスタイルコピーで、サブテキストと区切り線の見た目まで移る
-   スタイルコピーでメインテキストとサブテキストの内容は変わらない
-   画面幅別設定がPC、タブレット、スマートフォンで反映される
-   yStandardと他テーマの両方で、テーマ見出しスタイルのクリア設定が機能する

画面確認はLocal上の対象サイトで行う。ブラウザ自動操作を使う場合は、実装完了後に確認目的と対象画面を示して了承を得てから実施する。

## 完了条件

-   サブテキストなしでは、コア見出しと同程度の手数で作成と調整ができる。
-   サブテキストと区切り線を使う見出しを、ブロックを組み合わせず1ブロックで作れる。
-   タイポグラフィ、余白、枠線、角丸はコアUIで設定できる。
-   必要な独自項目を`+`メニューから表示できる。
-   単一設定とレスポンシブ設定が別パネルにあり、同時に保持できる。
-   各画面幅ではレスポンシブ設定が単一設定より優先され、未設定なら単一設定へ戻る。
-   独自設定を含む見た目を、同じカスタム見出しへ一度のスタイル貼り付けで移せる。
-   スタイル貼り付けで本文は変わらない。
-   既存の`ystdb/custom-heading`投稿が無効ブロックにならない。
-   変換操作で既存の`ystdb/heading`の内容や見た目を黙って失わない。
